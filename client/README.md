# 안심케어 클라이언트 (늘봄)

**팀 공명** · Flutter 앱 · 어르신용 / 보호자용 화면을 역할로 분기합니다.

이전 프로젝트(`aosxou/elder-care-app`)의 화면 자산을 가져와, 안심케어의 API 계약(설계 5장)에 맞춰 재구성한 것입니다.

---

## 실행

```bash
flutter pub get

# fixture 모드 (기본) — 백엔드 없이 화면 개발
flutter run

# 실서버 연결
flutter run --dart-define=USE_FIXTURES=false \
            --dart-define=API_BASE_URL=https://api.example.com
```

`USE_FIXTURES=true`가 기본입니다. 설계 2장의 **"프론트는 계약에 맞춘 fixture로 개발한다"** 를 그대로 구현한 것으로, 백엔드가 없어도 보호자 화면이 실제 형식의 데이터로 그려집니다. 서버가 붙으면 fixture만 실측으로 바뀌고 **화면 코드는 바뀌지 않습니다.**

### 검증

```bash
flutter analyze   # 오류 0건이어야 한다
flutter test
```

## 역할 분기

한 앱을 어르신과 보호자가 함께 씁니다. 첫 실행에서 역할을 한 번 고르면 기기에 저장되고, 다음부터는 곧바로 해당 화면으로 들어갑니다. 정식 계정 시스템은 범위 밖이므로(설계 2장) 로그인 대신 이 한 단계만 둡니다.

역할을 다시 고르려면 앱 데이터를 지우거나 `RoleStore.clear()`를 호출합니다.

**두 선택지의 크기가 다른 것은 의도입니다.** 어르신 쪽 카드가 더 큰 것은 장식이 아니라 저시력·손떨림 사용자에게 실제로 필요한 터치 영역입니다.

## 보호자 화면이 큰 숫자를 안 보여주는 이유

설계 3.2가 **"절대값보다 개인 기준선 대비 변화"** 로 위험을 판정합니다. 화면도 그걸 따릅니다.

- 지표는 항상 **`말수 31% / 평소 50%`** 처럼 쌍으로 붙습니다. `0.31`이라는 값 자체는 보호자에게 의미가 없습니다.
- 추이 막대에서 **미응답 날은 0이 아니라 빈 칸**입니다. 0으로 그리면 "아주 좋음"으로 읽혀 정반대 뜻이 됩니다.
- **위험 등급은 서버가 준 값을 그대로 표시**합니다. 앱이 점수를 보고 다시 판단하지 않습니다 — 판정 로직이 두 곳에 생기면 서로 어긋납니다.
- `risk_level`이 `null`이면 "측정하지 못했어요"로 표시합니다. 임의 점수를 만들지 않습니다(설계 8장).

## 아직 남은 것

- **Firebase 설정이 이전 프로젝트 것입니다.** `lib/firebase_options.dart`와 `android/app/google-services.json`을 새 프로젝트 설정으로 교체해야 알림이 동작합니다. 지금은 초기화가 실패해도 앱이 뜨도록 감싸 뒀습니다.
- **앱 통화(`calling_screen`)가 UI 껍데기입니다.** 타이머와 애니메이션만 있고 오디오 코드가 없습니다. 마이크 캡처 → WebSocket → 서버 왕복을 붙여야 합니다(설계 3.1-a).
- **앱 채널 글 대화(`ai_chat_screen`)** 는 음성이 없어 지표가 일부만 나옵니다(`degraded`).
- 보호자 화면은 홈 하나입니다. 알림 목록·설정이 붙을 자리를 `GuardianShell`에 남겨 뒀습니다.
- **한글 입력은 에뮬레이터에서 깨집니다.** AVD·BlueStacks 모두 네이티브 앱에서도 동일하게 깨지는 것을 확인했습니다. 앱 문제가 아니므로 **실기기에서 검증**하세요.
