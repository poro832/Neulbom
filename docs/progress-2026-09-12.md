**확인 완료 (2026-09-12)** — ClawOps 공식 API에 **SIP Endpoints · Routes · ACLs · Credentials**가 있고 라우트는 `sip:host[:port]`(udp/tls)입니다. **`SIP 직접연결` 애드온(월 99,000원)** 이 외부 SIP 시스템 연결을 열어 줍니다(자격증명 + IP 허용목록). 표준 SIP이라 Asterisk 연동이 가능합니다.

**그리고 Asterisk는 선택이 아니라 필수로 확인됐습니다.** ClawOps 관리형 AI 경로는 STT·LLM이 **OpenAI**, TTS가 **Cartesia/xAI** 고정이고 **CLOVA가 없으며**, 커스텀 엔드포인트도 실시간 오디오 스트리밍도 제공하지 않습니다. 관리형을 쓰면 설계 3.5(CLOVA 단일 스택)를 통째로 포기해야 합니다.

**남는 제약 — 비용입니다.** 기존 문서의 "월 19,000원"은 관리형 경로 요금이었습니다. Asterisk를 붙이려면 **월 118,000원(개인 + 애드온) ~ 198,000원(비즈니스 + 애드온)** 입니다. 애드온이 개인 요금제에 붙는지, 무료체험에 포함되는지, 그리고 **우리가 거는 아웃바운드 방향에서 070 발신번호 지정이 되는지**는 문의로 확인해야 합니다.

> **Asterisk를 다시 들인 것은 이전 판단을 뒤집는 것입니다.** 그때 접은 이유(SIP·NAT·RTP·SBC 부담)는 지금도 유효합니다. 바뀐 것은 **번호·트렁크를 ClawOps가 대면서 Asterisk가 맡을 범위가 통화 제어 하나로 줄었다**는 점입니다.

## 3. 검증된 사실

추측이 아니라 실제로 돌려서 확인한 것들입니다.

### 원 기획안 DDL은 실행 자체가 안 됩니다

컨테이너에서 재현했습니다.

```
ERROR:  relation "original_guardians" does not exist
```

`elders`가 아직 만들어지지 않은 `guardians`를 참조합니다. PostgreSQL은 전방 참조를 허용하지 않습니다. 순서를 바로잡은 수정판은 정상 적용됐습니다.

### 스키마 검증 통과

```
테이블 7 · 인덱스 17 · 외래키 8 · CHECK 제약 23
정상 경로(보호자→어르신→통화→전사→지표→요약→알림) 삽입 성공
미응답 통화도 오디오 없이 기록됨
음성 테스트 8건 전부 의도대로 거부
```

특히 `calls_completed_requires_audio` — 통화가 끝났다는데 분석할 오디오가 없으면 **파이프라인이 조용히 멈춥니다.** DB에서 막습니다.

### VadSegmenter — 전화 음질에서 결함을 찾았습니다

8kHz·μ-law·회선 잡음 조건으로 테스트했더니 **3개가 실패**했습니다.

| 조건 | 결과 |
|---|---|
| 8kHz 분절 | 이상 없음 |
| μ-law 압축 | 이상 없음 |
| 회선 잡음 오탐 | 이상 없음 |
| **조용한 어르신 음성** | **전부 놓침** |

8kHz도 μ-law도 문제가 아니었습니다. **고정 임계값 `rms_threshold = 0.02`가 문제**였습니다. 회선 잡음이 RMS 0.005 수준인데 목소리가 작은 어르신은 0.015로 들어옵니다. 잡음의 3배인데도 고정 임계값에 걸려 발화가 통째로 무음 처리됐습니다.

**놓치는 대상이 정확히 우리가 잡아야 할 사람들입니다.** 위험 지표가 "발화량이 줄었다"를 보는데, 그런 분들의 발화를 못 잡으면 `speech_ratio`가 0에 가깝게 나오고 지표가 무의미해집니다. 조용히 실패하는 종류라 골든셋 없이는 발견하기 어려웠을 겁니다.

수정: **잡음 바닥 기준 적응형 임계값**

```
임계값 = max(0.008, 잡음바닥 × 2.5)
        └ 절대 하한        └ 하위 10백분위 (피크의 30%로 상한)
```

세 조건을 동시에 만족시켜야 했습니다 — 절대 하한이 없으면 통화 전체가 잡음일 때 잡음을 발화로 세고, 피크 대비 상한이 없으면 통화 전체가 발화일 때 **자기 발화를 지워버립니다**(실제로 기존 16kHz 테스트가 이걸로 깨졌습니다).

### MetricsCalculator — 간판 기능 검증

```python
def test_score_is_identical_across_repeated_runs():
    scores = {assess_risk(metrics, ...).risk_score for _ in range(100)}
    assert len(scores) == 1
```

같은 입력 100회 → **점수 편차 0**. 설계 목표 "같은 오디오 재분석 시 위험 점수 편차 0"을 코드로 증명합니다.

### 테스트로 고정한 설계 결정

- **미응답은 지연 0이 아니라 `None`** — "즉답"과 구분되지 않으면 평균이 왜곡됩니다
- **마지막 AI 발화(작별 인사) 뒤 응답 없음은 세지 않음** — 세면 모든 통화의 지연이 부풀려집니다

## 6. 미해결 — CareCall 대비 포지셔닝

**네이버 클로바 케어콜이 이미 전국 229개 지자체 중 128곳에 도입돼 있습니다** (이용자 약 3만 명, 응답률 96%). 하는 일이 우리와 거의 같고, 우리가 쓰려는 CLOVA API의 그 회사입니다.

심사에서 **"네이버 케어콜이랑 뭐가 다른가요?"** 는 반드시 나옵니다. 전화 경로는 방법의 문제였지만 이건 **왜 만드느냐**의 문제라 발표 전체를 좌우합니다.

제안한 방향은 **"지자체가 못 가는 개인·가족용 + 수치 신뢰성"** 입니다.

- CareCall은 **지자체 계약 기반** — 개인·가족이 직접 신청할 수 없습니다. 128곳 도입은 **101곳은 아직 없다**는 뜻입니다
- CareCall의 리포트는 **지자체 담당자용** — 가족 보호자용 대시보드는 다른 사용자입니다
- **점수 재현성은 CareCall도 내세우지 않습니다** — 우리 간판이 여기입니다

이게 정해져야 설계 1장(목표)과 경쟁 분석을 확정할 수 있습니다.
