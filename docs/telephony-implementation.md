# 전화 구현 방법 — ClawOps 070 + Asterisk

**팀 공명** · 안심케어 · 2026-09-12 (개정 4판)

설계 문서 3.1의 전화 경로를 실제로 어떻게 구현할지 정리한 문서입니다.

> **개정 이력**
> - 1판 — Asterisk 자체 구축 채택
> - 2판 — Twilio Media Streams가 양방향 실시간 오디오를 제공한다는 사실을 확인해 Twilio로 변경
> - 3판 — 국내 070 번호를 쓸 수 있는 ClawOps로 변경. Twilio는 폴백
> - **4판 — ClawOps(번호·트렁크) + Asterisk(통화 제어·실시간 미디어) 조합으로 확정.** 둘 중 하나를 고르는 문제가 아니었습니다

---

## 1. 전화를 걸려면 무엇이 필요한가 — 그리고 이 조합이 나온 이유

```
① 전화번호        ← 통신사 발급. 전기통신사업법상 명의자 인증 필요
② PSTN 연결(트렁크) ← 통신사와 계약
③ 통화 제어        ← 소프트웨어
```

1판부터 이 셋을 적어두고도 **양자택일로 다뤄 왔습니다.** 그런데 셋은 한 덩어리가 아닙니다.

| | ① 번호 | ② 트렁크 | ③ 통화 제어 · 미디어 |
|---|---|---|---|
| **CPaaS** (ClawOps·Twilio) | ✅ 판다 | ✅ 판다 | 자기네 API로만. **우리가 못 건드림** |
| **Asterisk** | ❌ 직접 구해와야 | ❌ 직접 구해와야 | ✅ **전부 우리 것** |

**서로의 빈칸을 정확히 메웁니다.** ClawOps에서 070 번호와 트렁크를 사고, 통화 제어와 실시간 미디어는 우리 Asterisk가 잡습니다.

이 조합이 3판까지 남아 있던 가장 큰 불확실성을 없앱니다 — **"ClawOps가 통화 중 오디오를 실시간으로 내줄까?"** 를 더 이상 기다릴 필요가 없습니다. SIP를 우리가 종단하므로 RTP가 우리 서버로 직접 들어옵니다.

## 2. 검토한 경로와 판정

| 경로 | 번호 | 판정 | 근거 |
|---|---|---|---|
| **통신 3사 API** | — | ❌ | KT API Link의 `AI_GENIE`는 **기가지니 단말용 SDK**(STT/TTS/대화). 발신·통화제어 API가 없음. 음성 상품은 전부 **AICC = B2B 구축 계약** |
| **국내 CPaaS** (NCP SENS, NHN Cloud) | — | ❌ | **SMS·알림톡만** 제공 |
| Asterisk **단독** | 별도 확보 | ❌ | ③은 완벽하나 ①②를 못 구함. 개인이 국내 번호와 트렁크를 직접 계약하는 건 4주 밖 |
| ClawOps **단독** | 070 | ❌ | ①②는 해결. 그러나 ③이 업체 API에 묶이고 **관리형 AI 경로가 OpenAI/Cartesia 전용 — CLOVA를 못 씀**(4장 확인) |
| **Twilio** | 해외 | **폴백** | 실시간 오디오 확실(Media Streams). 다만 **어르신에게 해외번호로 표시** |
| **ClawOps + Asterisk** | **070** | ✅ **채택** | ①② ClawOps, ③ Asterisk. 국내 번호와 실시간 미디어를 **동시에** 얻음 |

> **한국은 발신번호 변작이 불법**입니다(전기통신사업법). 남의 번호를 발신번호로 띄우는 우회는 불가능합니다.

## 3. 이 조합이 주는 것

**국내 070 번호.** Twilio를 쓰면 어르신 화면에 해외번호가 뜨고, 실제 독거노인은 받지 않습니다. 그러면 "설치 불필요·전화기만 있으면 된다"는 서비스의 1번 가치가 시연용으로만 성립합니다.

**실시간 양방향 오디오를 업체 지원에 기대지 않습니다.** Asterisk가 SIP를 종단하므로 RTP 스트림이 우리 서버로 들어옵니다. 설계 3.3의 지연 대책 3개(발화 종료 직접 감지 · 즉시 반응 오디오 · TTS 스트리밍)가 전부 구현 가능합니다.

**CLOVA 단일 스택이 지켜집니다 — 이게 Asterisk를 넣는 진짜 이유입니다.** ClawOps 관리형 경로는 STT·LLM이 OpenAI, TTS가 Cartesia/xAI로 **고정**이고 커스텀 엔드포인트도 오디오 스트리밍도 없습니다(4장). 미디어를 우리가 받아야만 설계 3.5가 성립합니다.

### ClawOps 쪽 사양 (2026-09-12 공식 문서·요금표 확인)

| 항목 | 내용 |
|---|---|
| 번호 발급 | `POST /v1/accounts/{id}/numbers` → **070 즉시 발급**, 통신사 심사 대기 없음 |
| 발신 | `POST /v1/accounts/{id}/calls` — `To` / `From` / `StatusCallback` |
| **SIP 트렁크 API** | `GET /v1/accounts/{id}/sip-endpoints` 외 — **SIP Endpoints · Routes · ACLs · Credentials** |
| **라우트 형식** | `sip:host[:port]` / `sips:host[:port]`, transport **udp 또는 tls**, priority·weight 기반 분배 |
| 웹훅 | `call.started`, `call.ended`, `recording.completed`, `transcript.completed`, `summary.completed` |
| 인프라 | RFC 3261 SIP/2.0 · SRTP · DTMF |
| 무료 체험 | 3일, 1회선, 아웃바운드 10분 — 카드 등록 불필요 |
| 개인 요금제 | 월 19,000원 — 1회선, 아웃바운드 100분, 인바운드 1,000분 |
| **SIP 직접연결 애드온** | **월 99,000원** — 외부 플랫폼이 SIP로 ClawOps 070 인프라에 직접 붙는 기능. **자격증명 + IP 허용목록** 설정 필요 |
| 아웃바운드 종량 | ₩60/분 (0\~10,000분 구간) |

> **비용 정정.** 3판까지 "월 19,000원"으로 적었지만 그건 **관리형 경로**의 요금입니다. **우리 Asterisk를 붙이려면 `SIP 직접연결` 애드온(월 99,000원)이 필요**합니다. 요금제까지 더하면 **월 118,000원(개인 + 애드온) ~ 198,000원(비즈니스 + 애드온)** 입니다. 애드온이 개인 요금제에도 붙는지는 문의로 확인해야 합니다.

### 비용을 낮추는 방법

애드온 99,000원이 전체의 **84%** 입니다. 그게 하는 일은 하나 — 우리 Asterisk가 SIP으로 붙게 해주는 것.

| 레버 | 효과 | 상태 |
|---|---|---|
| **① 기간 압축** | 1~3주차는 앱 채널로 개발, 전화망은 **4주차 1개월만** 결제 | ✅ 바로 적용 가능 |
| **② 국내 개인용 070 회선** | 온누리070 등 **월 2,000원대**. 애드온이 통째로 사라짐 | ⚠️ 약관 확인 필요 |
| **③ EC2** | 프리티어면 12개월 무료 | ⚠️ **계정 미확보** — 회사 계정은 권한 없음 |
| ④ 학교·클라우드 크레딧 | CLOVA 사용료까지 같이 덮음 | 확인 필요 |

**②가 가장 큽니다.** Asterisk는 트렁크 제공자를 가리지 않습니다 — ClawOps여야 할 이유가 없습니다. 국내 개인용 070 인터넷전화는 SIP 계정을 그대로 내주고(원래 용도는 "다른 소프트폰에 넣어 쓰라"), Asterisk도 같은 SIP UA입니다. **월 2,000~7,000원이면 50분의 1입니다.**

단, 소비자용 회선이라 **약관이 PBX 연결이나 자동 발신을 금지할 수 있습니다.** 회선도 1개(동시 통화 1건, 시연엔 충분). 사업자 고객센터에 물으면 바로 답이 나옵니다.

```
개발 1~3주   앱 채널만                     0원
4주차        ② 되면  월 2,000~7,000원
             ② 막히면 ClawOps 1개월 118,000원
```

**최선 ~1만원, 최악 12만원.**

> **6장 어댑터 분리가 여기서 값을 합니다.** ②로 가면 ClawOps를 아예 안 쓰게 되는데, 트렁크와 통화 제어를 나눠 뒀으므로 **`AsteriskAdapter` 안쪽은 그대로**입니다. 발표에서 "업체 종속을 피하려고 계층을 나눴고 실제로 갈아끼웠다"로 설명됩니다.

### EC2 쪽 확인 사항

Asterisk는 일반 웹서버와 네트워크 요구가 다릅니다.

| 필요한 것 | 이유 |
|---|---|
| **Elastic IP** | 트렁크 사업자가 IP를 허용목록에 등록. IP가 바뀌면 끊김 |
| **UDP 5060** | SIP 시그널링 |
| **UDP 10000~20000** | RTP 음성. 포트 범위가 넓음 |

조직이 관리하는 계정이면 **보안 그룹에서 UDP 대역을 여는 것이 정책으로 막혀 있을 수** 있습니다. 4주차에 막히지 않도록 **계정 권한을 미리 확인**해 둡니다.

## 4. 확인되지 않은 것 — 1주차 Day 1 검증 항목

<!-- 이 절이 이 문서에서 가장 중요합니다. 3판의 미확인 항목이 바뀌었습니다. -->

> ✅ **2026-09-12 확인 — SIP 트렁크는 존재합니다.** 공식 API에 **SIP Endpoints · Routes · ACLs · Credentials**가 있고, 라우트는 `sip:host[:port]`(udp/tls)로 지정합니다. 별도 상품인 **`SIP 직접연결` 애드온(월 99,000원)** 이 "외부 플랫폼에서 ClawOps 070 인프라로 직접 SIP 연결"을 열어 주며, **자격증명 + IP 허용목록**으로 설정합니다. Asterisk가 이름으로 적혀 있진 않지만 **RFC 3261 표준 SIP**이므로 붙지 않을 이유가 없습니다.

### 그리고 Asterisk는 선택이 아니라 필수입니다

<!-- 3판의 리스크가 사실로 확인됐습니다. -->

ClawOps **관리형 AI 경로에는 CLOVA가 없습니다.** 공식 문서 기준 지원 제공자는 다음이 전부입니다.

| 계층 | ClawOps가 지원하는 것 | 우리가 쓰려는 것 |
|---|---|---|
| STT | OpenAI (`gpt-4o-transcribe`, `whisper-1`) | **CLOVA Speech Recognition** |
| LLM | OpenAI (Realtime / GPT 계열) | **CLOVA Studio (HyperCLOVA X)** |
| TTS | Cartesia, xAI | **CLOVA Voice** |

**임의의 커스텀 STT/TTS/LLM 엔드포인트를 꽂는 기능도, 통화 오디오를 실시간으로 받아가는 스트리밍 API도 문서에 없습니다.**

3판에서 "실시간 경로가 OpenAI 전용일 가능성"을 리스크로 적었는데, **사실로 확인됐고 범위는 더 넓었습니다.** 관리형 경로를 쓰면 설계 3.5(CLOVA 단일 스택)를 통째로 포기해야 합니다. 오디오를 우리가 받으려면 **SIP를 직접 종단하는 수밖에 없고, 그게 Asterisk입니다.**

### 남은 미확인 항목

1. **`SIP 직접연결` 애드온이 개인 요금제(월 19,000원)에도 붙는가**, 아니면 비즈니스 전용인가 ← **예산이 여기서 갈립니다**
2. **3일 무료체험에 이 애드온이 포함되는가** — 포함 안 되면 "검증 비용 0"이 성립하지 않습니다
3. **코덱** — G.711 μ-law 8kHz인가. 맞으면 우리 VAD가 그대로 붙습니다 (문서에 명시 없음)
4. **아웃바운드 방향** — 우리 Asterisk에서 ClawOps 트렁크로 걸어 나갈 때 **발신번호를 070으로 지정**할 수 있는가. 공개 문서의 SIP Endpoint 설명은 *"outbound SIP trunk routing"*, 즉 ClawOps → 우리 SIP URI 방향 위주라 **우리가 거는 방향은 확인이 필요**합니다
5. **사업자등록증이 필요한가** (문서에 명시 없음)

4번이 설계상 가장 중요합니다. 우리는 **아웃바운드 주력**(설계 3.1)이라 우리가 어르신께 거는 방향이 막히면 구조가 흔들립니다.

> **문의로 확인하는 편이 빠릅니다.** 1·2·4번은 공개 문서로 판별되지 않아 무료체험만으로는 답이 안 나옵니다.

| | 애드온 확보 | 애드온 못 씀 | 070 자체가 안 됨 |

## 5. 아키텍처

```
[EventBridge] 매일 09:00
      │
      ▼
[발신 Lambda] ── ARI: POST /channels ──▶ [Asterisk]
                                              │
                                    SIP/RTP (070 발신)
                                              │
                                         [ClawOps 트렁크]
                                              │
                                              ▼
                                        어르신 휴대폰
      ┌───────────────────────────────────────┘
      │  통화 중 — RTP가 우리 서버로 직접
      ▼
[Asterisk (EC2, Elastic IP)]
 ├─ chan_pjsip     : ClawOps 트렁크 연동
 ├─ ARI            : 발신·통화 제어 (REST + WebSocket 이벤트)
 ├─ AudioSocket    : 통화 오디오를 TCP로 우리 앱에 전달 (SLIN 8kHz)
 └─ MixMonitor     : 통화 녹음 → S3
      │
      ▼  AudioSocket (양방향)
[대화 핸들러 (EC2 동거 또는 ECS)]   ← 유일한 상주 컴포넌트
 ├─ 수신 프레임 → VadSegmenter → 발화 종료 감지
 ├─ 즉시 반응 오디오 송출 (0.5초 내)
 └─ CLOVA Speech → 의도 분류 → 캐시 오디오 / CLOVA Studio + Voice
      │
      │  통화 종료 → 녹음 S3 저장 → SQS 발행
      ▼ SQS (표준 큐 + DLQ)
[분석 워커 Lambda]   ← 기존 설계 그대로. 전화 경로와 무관.
 ├─ VadSegmenter      : 오디오 → 발화/침묵 구간 (순수)
 ├─ Transcriber       : CLOVA Speech → 전사문
 ├─ MetricsCalculator : 지표·위험 점수 (순수)
 ├─ ReportWriter      : CLOVA Studio → 요약·설명
 └─ AlertDispatcher   : 위험 상승 시 SMS/이메일
      │
      ▼
[RDS PostgreSQL]   [S3: 녹음 + TTS 캐시]   [보호자 대시보드]
```

**분석 계층은 전화 경로와 완전히 분리돼 있습니다.** 경로를 네 번 바꾸는 동안 분석 코드는 한 줄도 바뀌지 않았습니다.

### Asterisk를 EC2에 두는 이유

SIP과 RTP는 **고정 IP와 넓은 UDP 포트 범위**를 요구합니다. Fargate는 태스크마다 IP가 바뀌고 포트 매핑이 동적이라 NAT 통과가 까다롭습니다. **Elastic IP를 붙인 EC2 한 대**가 정석이고, 4주 안에 확실한 선택입니다.

### AudioSocket을 쓰는 이유

Asterisk 18+의 `AudioSocket`은 오디오를 **TCP로 SLIN(부호 있는 선형 PCM) 8kHz** 프레임으로 넘깁니다.

- 우리 `VadSegmenter`는 이미 **8kHz에서 검증**돼 있습니다 (테스트 6개)
- μ-law 압축 손실 없이 원본 PCM을 받습니다 — 압축→복원 단계가 사라집니다
- 프로토콜이 단순해 파이썬으로 몇십 줄이면 붙습니다

## 6. 전화 계층을 추상화합니다

```
[통화 제어 앱]
      ↑ 얇은 인터페이스
      │  place_call() / on_audio_chunk() / send_audio()
      │  on_recording_ready() / on_call_ended()
      ▼
[전화 어댑터]
  ├─ AsteriskAdapter   (채택 — ARI + AudioSocket)
  │    └─ 트렁크: ClawOps(070) ⇄ 교체 가능
  ├─ ClawOpsRestAdapter (트렁크 미제공 시 — REST 직접)
  └─ TwilioAdapter      (070 자체가 안 될 때)
```

**어댑터 경계가 4판에서 더 깨끗해집니다.** 트렁크(누가 PSTN에 연결해 주는가)와 통화 제어(누가 오디오를 다루는가)가 분리되므로, 트렁크 업체가 바뀌어도 `AsteriskAdapter` 안쪽은 그대로입니다.

## 7. 남은 리스크

| 리스크 | 대응 |
|---|---|
| **애드온 비용(월 99,000원)이 예산을 넘음** | 4주 프로젝트 총 12~20만원 수준. 팀 4명이면 감당 가능하나 **사전 합의 필요** |
| **우리가 거는 방향(아웃바운드) 미확인** | 공개 문서는 ClawOps → 우리 SIP URI 방향 위주. Day 1 문의로 확인. 막히면 Twilio + Asterisk |
| **SIP·NAT·RTP 운영 부담이 돌아옴** | 1판에서 Asterisk를 접은 이유가 이것입니다. 단 이번엔 ①②를 직접 구할 필요가 없어 부담이 **③으로 한정**됩니다. 1명 전담 · 1주차 안에 Hello World가 목표 |
| **상주 서버가 생김** | EC2 1대가 단일 장애점. 4주 프로젝트에선 감수하고, 발표에선 이중화 로드맵으로 설명 |
| **사업자등록 요구** | 미확인. 요구되면 팀원 명의 또는 Twilio 폴백 |
| **아웃바운드 100분/월** | 3~5분 통화 20~30회. 개발 테스트엔 충분하나 넉넉하지 않음 |
| **070을 스팸으로 인식** | 해외번호보다는 훨씬 낫지만 여전히 존재. 사전 안내 문자 병행 검토 |

> **정직하게 적어 둡니다.** Asterisk를 다시 들인 것은 1판의 판단을 뒤집는 것입니다. 그때 접은 이유(SIP·NAT·RTP·SBC 부담)는 지금도 유효합니다. 바뀐 것은 **번호 문제가 ClawOps로 풀려서, Asterisk가 감당해야 할 범위가 ③ 하나로 줄었다**는 점입니다.

## 8. 발표 관점

**"국내 070 번호로 실제 전화가 가고, 통화 오디오를 우리가 직접 다룹니다."**

두 가지를 동시에 말할 수 있는 구성입니다. 3판까지는 둘 중 하나를 포기해야 했습니다 — Twilio면 실시간은 되지만 해외번호, ClawOps 단독이면 070은 되지만 실시간이 업체 손에 있었습니다.

경로 선택 과정 자체도 설명거리입니다. 통신 3사 API 부재, 국내 CPaaS의 SMS 한정, 발신번호 변작 규제를 조사하고, **번호·트렁크·통화제어를 분리해서 보니 조합이 답이었다**는 흐름은 시장과 기술을 함께 이해하고 있다는 신호입니다.
