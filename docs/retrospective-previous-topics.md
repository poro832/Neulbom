## 그대로 가져온 것

두 번 만들면서 검증된 것들입니다. 도메인이 바뀌어도 대부분 재사용됐습니다.

### 아키텍처 패턴

- **비동기 잡 구조** — `API는 접수만 → 큐 → 워커 → 폴링`. 무거운 AI 처리가 있으면 거의 항상 필요합니다
- **경량 인증** — 디바이스 UUID. 4주 프로젝트에서 Cognito는 과합니다. `user_id`로 승격 가능하게 인터페이스만 열어 둡니다
- **presigned URL 직접 업로드** — 큰 파일(이미지·오디오)은 API를 거치지 않고 스토리지로
- **`degraded` 플래그** — 분석 품질이 낮을 때 실패로 처리하지 않고 "정확도 낮음"을 정직하게 표시

### 스키마 관례

- 상태·분류 컬럼에 CHECK 제약
- `error_code`는 `status='failed'`일 때만 허용하는 **교차 제약**
- 워커 재시작용 **부분 인덱스** (`WHERE status IN ('queued','running')`)
- **스냅샷 컬럼** — 원본이 바뀌거나 삭제돼도 이력이 어긋나지 않게

안심케어에서 이 관례가 `calls_completed_requires_audio`, `calls_app_cannot_be_no_answer` 같은 제약으로 이어졌습니다.

### 코드

- **`VadSegmenter`** — 면접 코칭의 발화량·침묵·응답지연 측정 코드가 **그대로** 안심케어의 위험 지표가 됐습니다. 외부 의존이 없어 이식이 간단했습니다
- **`FillerDetector`의 사전 매칭** — 필러워드(음/어/그) 탐지 로직이 부정 표현(아프다/힘들다/외롭다) 탐지로 거의 그대로 옮겨졌습니다

## 작업 방식 — 이게 가장 큰 자산입니다

- **계약(JSON)을 먼저 고정하고 fixture로 백엔드를 완주** — 프론트가 늦어도 안 멈춥니다
- **스키마는 실제 컨테이너에 적용해 검증** — 제약 위반 음성 테스트까지
- **순수 함수로 잘라서 TDD** — 클라우드 없이 로컬에서 도는 컴포넌트를 먼저
- **골든 평가셋으로 정량 목표** — "재현율 85%" 같은 숫자를 발표에 쓸 수 있게
- **LLM은 숫자를 만들지 않는다** — 정량 지표는 결정론적으로 계산하고 LLM은 설명만

## 주제를 정할 때 확인할 것

두 번의 중단에서 얻은 항목입니다. 안심케어에도 그대로 적용했습니다.

1. **같은 공모전·수업에 겹치는 팀이 있는지 먼저 확인.** 음성 면접 코칭은 설계를 끝내고 구현까지 들어간 뒤에 MYPASS와의 중복을 발견했습니다.
2. **간판 기능 하나를 정하고, 그게 정량 측정 가능한지 확인.** 심사에서 "이게 잘 되는 걸 어떻게 아느냐"에 답할 수 있어야 합니다. 안심케어의 답은 **위험 점수 재현성**입니다.
3. **핵심 기술 전제를 1주차에 실측.** 이전 두 주제 모두 전제가 틀릴 뻔했습니다 — AWS Textract 한국어 미지원, Whisper의 필러워드 제거, Whisper의 Lambda 실행 불가.
4. **4주에 끝나는 범위인지.** 좁고 깊게가 넓고 얕게보다 낫습니다.

3번은 안심케어에서도 값을 했습니다. ClawOps 관리형 경로가 **CLOVA를 지원하지 않는다**는 사실을 공식 문서에서 확인하고 전화 경로를 바꿨습니다 (`docs/telephony-implementation.md` 4장).
